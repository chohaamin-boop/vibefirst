## 1. 서비스 개요

누구나 질문 하나와 **선택지 3개**로 투표를 만들고, 생성된 링크를 공유해 다른 사람이 투표할 수 있는 웹사이트.

**사용 예시**
- 질문: `오늘 저녁 뭐 먹을까?`
- 선택지: `치킨 / 피자 / 햄버거`
- 투표 결과: `치킨 2표(67%), 피자 1표(33%), 햄버거 0표(0%)`

**사용 흐름:** 투표 생성 → 공유 링크(`/p/{id}`) 발급 → 친구들이 투표 → 결과 그래프 확인

## 2. 이번 연습에서 구현할 기능

| 구분 | 요구사항 |
|---|---|
| 투표 생성 | 질문 1개 + 비어 있지 않은 선택지 3개 입력 |
| 링크 공유 | 생성 후 `/p/{id}` 페이지로 이동, 현재 URL 복사 가능 |
| 투표 참여 | 3개 중 1개를 선택해 제출 |
| 중복 투표 제한 | 투표 후 `localStorage` 기록을 확인해 같은 브라우저에서 재투표 제한 |
| 결과 표시 | 선택지별 득표수와 백분율 막대그래프 |
| 결과 갱신 | 결과 페이지에서 3초마다 API를 재조회 |

**범위 제외:** 로그인, 회원가입, 댓글, 투표 수정/삭제, 이미지 업로드, 복잡한 관리자 기능, AI 연동.

> 중복 투표 제한은 연습용 UI 수준이다. 다른 브라우저나 저장소 초기화로 우회할 수 있으며 실제 서비스의 부정 투표 방지와는 다르다.

## 4. 팀원별 작업 분담

### A - 투표 생성 화면 (`feat/create-poll`)
- `/` 페이지에서 질문과 선택지 3개를 입력할 수 있게 만든다.
- 입력 검증: 질문과 선택지가 비어 있으면 제출하지 않는다.
- `POST /api/polls` 호출 후 `/p/{id}`로 이동한다.
- **완료 기준:** 테스트 질문으로 투표를 생성하고 공유 가능한 주소가 열린다.

### B - 투표 참여·결과 화면 (`feat/vote-ui`)
- `/p/[id]` 페이지에서 질문과 선택지 3개를 표시한다.
- 사용자가 선택지를 누르면 `POST /api/polls/{id}/vote`를 호출한다.
- 투표 완료 후 `localStorage`로 재투표를 제한한다.
- 선택지별 표수·백분율을 그래프로 보여주고 3초마다 새 결과를 가져온다.
- **완료 기준:** 서로 다른 브라우저 3개에서 투표한 결과가 표시된다.

### C - DB·API (`feat/backend`)
- Supabase에 `polls`, `votes` 테이블을 만든다.
- 투표 생성, 상세 조회, 투표 제출 API를 구현한다.
- 서버에서 질문·선택지·선택 번호를 검증하고 오류를 반환한다.
- **완료 기준:** 브라우저 없이 API만 호출해 투표 생성·조회·제출이 동작한다.

## 5. API 계약 (개발 시작 전에 공유)

### `POST /api/polls`
요청: `{ "question": "오늘 저녁 뭐 먹을까?", "options": ["치킨", "피자", "햄버거"] }`  
성공 응답: `{ "id": "uuid" }`

### `GET /api/polls/{id}`
성공 응답: `{ "id": "uuid", "question": "...", "options": ["치킨", "피자", "햄버거"], "counts": [2,1,0], "totalVotes": 3 }`

### `POST /api/polls/{id}/vote`
요청: `{ "optionIndex": 0 }` (`0`, `1`, `2` 중 하나)  
성공 응답: `{ "ok": true }`

**오류 정책:** 잘못된 입력은 HTTP 400, 존재하지 않는 투표는 404, 서버 오류는 500. 프론트엔드는 실패 시 에러 메시지를 보여준다.

**DB 최소 구조**
- `polls`: `id (uuid PK)`, `question (text)`, `options (jsonb)`, `created_at (timestamptz)`
- `votes`: `id (uuid PK)`, `poll_id (uuid FK)`, `option_index (int)`, `created_at (timestamptz)`

**보안 주의:** Supabase service role 키는 서버 환경변수에만 보관하고 브라우저 코드나 Git에 올리지 않는다. 서버에서 선택 번호 `0~2`를 확인한다.
