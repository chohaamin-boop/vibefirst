# 역할 분담

API 계약과 상세 요구사항은 [pick-one-plan.md](pick-one-plan.md)를 따릅니다. 담당자 이름은 정해지면 채웁니다.

| 역할 | 담당자 | 브랜치 | 작업량 |
| --- | --- | --- | --- |
| C: DB·API | 서버 담당 (TBD) | `feat/backend` | 중간 |
| B: 투표·결과 화면 | AI를 많이 쓰는 사람 (TBD) | `feat/vote-ui` | 많음 |
| A: 투표 생성 화면 | 적게 작업하는 사람 (TBD) | `feat/create-poll` | 적음 |

## C: DB·API (서버 담당)

- Supabase에 `polls`, `votes` 테이블 생성
- API 3개 구현: 투표 생성, 상세 조회, 투표 제출
- 서버에서 입력 검증, 오류는 400/404/500으로 응답
- Supabase 키는 서버 환경변수로만 관리하고 변수명은 `.env.example`에 추가
- 나머지 두 명이 기다리지 않도록 응답 형식(mock)을 가장 먼저 공유

## B: 투표·결과 화면 (작업량 많음)

- `/p/[id]`에서 질문과 선택지 표시
- 투표 제출 처리, `localStorage`로 재투표 제한
- 득표수·백분율 막대그래프, 3초마다 결과 재조회
- 오류 메시지 표시

## A: 투표 생성 화면 (작업량 적음)

- `/`에서 질문과 선택지 3개 입력 폼, 빈 값 검증
- `POST /api/polls` 호출 후 `/p/{id}`로 이동
- 추가 담당: Next.js 기본 세팅(`main`에 먼저 올리기), 공유 링크 복사 버튼, 공통 레이아웃·Tailwind 스타일, 배포, `AGENTS.md` "명령어" 섹션 채우기

## 주의

- 시작 전에 API 계약을 셋이 함께 확인합니다.
- A의 Next.js 세팅이 `main`에 올라온 뒤 B와 C가 브랜치를 만듭니다.
